# Agora 기억 애드온(AnchorMind) 실행 계획

## 1. 목표

AnchorMind(장기 기억 서버)를 Agora에 애드온으로 붙여, 프로젝트마다 장기 기억을 쌓고 꺼내 씁니다. 애드온을 켠 프로젝트에서는 사용자 메시지마다 관련 있는 기억만 골라 프롬프트에 넣고, 사람이 고른 내용(기억하기, 확정한 결정)과 기록관 요약을 저장합니다. AnchorMind 코드는 고치지 않고, 따로 설치한 서버를 Agora가 HTTP로 부릅니다.

## 5. 단계별 할 일

### 0단계: 임베딩을 Gemini 001로 전환

AnchorMind 설정만 바꾸고 Agora 코드는 건드리지 않습니다. 기억이 0건인 지금 바꾸면 다시 임베딩할 것이 없고, 기억이 쌓인 뒤에 바꾸면 모든 기억을 Google로 다시 보내야 합니다. 그래서 애드온을 쓰기 전에 합니다.

1. `.env`에서 `EMBEDDING_PROVIDER=gemini`, `EMBEDDING_MODEL=gemini-embedding-001`, `EMBEDDING_DIMENSIONS=3072`(AnchorMind 기본값)로 바꾸고, `GEMINI_API_KEY` 줄의 주석을 풉니다. 3,072차원은 Gemini의 기본 차원이라 `EMBEDDING_SUPPORTS_DIMS_PARAM`은 넣지 않습니다. 로컬 설정은 되돌리기용 주석으로 남깁니다. 로컬 임베딩 설정과 API 키가 함께 있으면 AnchorMind가 켜지자마자 멈추므로(`lib/config.js`) 한 번에 바꿉니다. 키 값은 화면이나 기록에 내지 않습니다.
2. 서버는 끈 채 DB만 켜고, `node scripts/post-migrate-flexible-embedding-dims.js --dry-run`으로 바뀔 내용을 본 뒤 실제로 실행합니다. 네 표(`fragments`, `morpheme_dict`, `fragment_synthetic_query`, `fragment_segment`)의 임베딩 칸이 `halfvec(3072)`로 바뀌고(2,000차원을 넘으면 AnchorMind가 halfvec를 씀), 들어 있던 임베딩은 비워집니다.
3. 형태소 사전에 남은 13행은 임베딩만 비고, 같은 낱말이 다시 쓰일 때 자동으로 다시 계산됩니다. 사전 전체를 다시 임베딩하는 `backfill-morpheme-dict.js`는 실행하지 않습니다.
4. `node scripts/check-embedding-consistency.js`를 플래그 없이 한 번 돌려 종료 코드 0을 확인한 뒤(`--record`는 차원을 검사하지 않음), `--record`로 임베딩 기록을 `gemini / gemini-embedding-001 / 3072`로 바꿉니다.
5. 서버를 켜고 기동 로그에 임베딩 경고가 없는지 봅니다. 로컬 임베딩 모델을 올리지 않으므로 서버 메모리가 얼마나 줄었는지 잽니다.
6. 6절의 실제 연결 1을 부록 문장 전체로 하고, 3,072차원의 점수를 7.1절 표에 더합니다(1-5의 첫 문턱값).
7. 서버와 DB를 끄고, `LOCAL_PREPARATION.md`에 현재 상태와 로컬로 되돌리는 절차를 적습니다.

- **완료 기준:** 기동 경고 없음, 실제 연결 1 통과, 시험 기억 0건.
- **되돌리기:** 서버를 끄고 `.env`의 Gemini 세 줄을 주석으로, `# [로컬]` 줄을 원래대로 돌리고 `GEMINI_API_KEY`를 다시 주석으로 바꾼 뒤(로컬 임베딩과 키가 함께 있으면 AnchorMind가 멈추므로 한 번에), 2번과 4번을 384차원으로 다시 합니다. 기억이 없으면 잃는 것이 없고 Google 호출도 없습니다.
- **결과(2026-10-24):** 기동 경고 없음, 서버 메모리 켠 뒤 약 0.65GB·저장·검색 뒤 약 0.72GB(로컬 1.1GB/1.0GB), 검색 하한 학습 행 8개(표본 12, 50 미만이라 쓰이지 않음), 시험 기억 0건, AnchorMind `git status` 깨끗함.

### 1단계: 애드온 기본 기능

- 지켜볼 것: 기억이 도움이 된 답, 관련 없는 기억이 붙은 경우, 필요한 기억이 붙지 않은 경우. 1-5에서 남긴 점수와 근거 상태도 함께 봅니다.
- 이 기간에 저장하는 기억과 검색 질문은 Google로 갑니다(임베딩).
- 관련 있는 경우와 없는 경우가 문턱값을 정할 만큼 모이면 2단계로 넘어갑니다. 실무 사용은 그 뒤에도 계속합니다.

### 2단계: 보정과 쓰기 확장

- **문턱값 보정:** 실무에서 모인 점수와 근거 상태로 다시 정합니다.
- **대기 한도:** 3초가 충분한지 잽니다. Gemini 호출만 0.4~0.6초가 걸립니다.
- **임베딩 전 공백:** 저장 직후 최대 5분은 의미 검색에 잡히지 않습니다. 실무에서 문제가 되는지 봅니다. 키워드 질의는 1-8에서 쓰지 않기로 했으므로, 문제가 되면 그때 방법을 정합니다.
- **쓰기 확장(실무에 써 본 뒤 정함):** 지휘 AI 제어 줄 `REMEMBER:`(설계안 4.4), 방 첫 메시지에 `context`로 핵심 기억 넣기. 기억 고치기(`amend`)는 1단계로 당겼습니다(2026-10-24).
- **Memory Bank:** 토큰을 줄이려면 Memory Bank 통째 주입을 골라 넣기로 바꿀지 다시 봅니다.

### 3단계: 운영

**3-1. 업데이트 확인.** 사용자가 매번 직접 확인하지 않아도 되게 합니다.

- 볼 것: AnchorMind 새 버전(릴리스 노트의 `gemini-embedding-2` 작업 지시 지원, 새 마이그레이션, 바뀐 도구 형식), Google 임베딩 폐기 일정(001 종료일 변경), pgvector 보안 수정.
- 방법 (가): Codex 자동 작업으로 한 달에 한 번 확인하는 방법은 쓰지 않습니다(2절 "업데이트 확인").
- 방법 (나): 애드온이 접속 키를 읽을 때 AnchorMind `.env`의 `EMBEDDING_MODEL`도 읽어, `gemini-embedding-001`이고 날짜가 2028-02-14(종료 석 달 전) 이후면 설정 창에 경고합니다. 네트워크 없이 날짜만 봅니다. 1-9 버전 경고와 같은 자리에 붙입니다. 1단계에서 만듭니다.
- AnchorMind는 6.7.1에 고정해 두므로 새 버전이 나와도 올리기 전까지는 영향이 없습니다. 새 버전마다 따라가지 않고, 필요한 기능이나 보안 수정이 있을 때만 올립니다.

**3-2. AnchorMind 올리는 절차.** 전용 DB 백업 → 새 버전 받기(`git fetch` 후 새 태그로 이동) → `npm ci --omit=dev` → `npm run migrate`(서버를 켜기 전에) → 서버 켜기 → 임베딩 일관성 검사 → 6절 실제 연결 1 → 애드온의 시험한 버전 갱신. AnchorMind 업그레이드 노트(`docs/operations/upgrade-notes.md`)의 공통 절차를 이 PC 방식에 맞춘 것입니다. 노트의 백업 스크립트(`scripts/ops/backup.sh`)는 bash용이라, Windows에서는 PostgreSQL 18의 `pg_dump`로 대신합니다(시험 전).

**3-3. `gemini-embedding-2`로 옮기기 (2028-05-14 전).**

- AnchorMind가 작업 지시 접두어를 지원하게 되면 그 설정을 씁니다.
- 지원하지 않으면 애드온이 `recall` 질의 앞에 `query: `를 붙입니다(7.1절 간격 +0.155). 이때 세 가지를 실제 서버에서 확인합니다.
  - `recall`의 `text`는 키워드 검색에도 쓰여 `query`라는 낱말이 섞일 수 있습니다.
  - AnchorMind가 질의를 바꾸고 정리하는 과정(`expandAssistantQuery`, `prepareTextForEmbedding`)을 거친 뒤에도 점수가 시험과 같아야 합니다.
  - AnchorMind가 안에서 만드는 질의(합성 질의, 모순 판정, 기억 연결)는 접두어 없이 임베딩됩니다.
- 차원이 같아도(3,072) 두 모델의 벡터는 서로 비교할 수 없어서 모든 임베딩을 다시 만들어야 합니다. 그런데 차원이 같으면 0단계 2번의 칸 변환이 아무것도 비우지 않고, `backfill-embeddings.js`는 비어 있는 임베딩만 채웁니다(6.7.1 기준). AnchorMind 업그레이드 노트 4번은 같은 차원이어도 이 스크립트로 다시 만들라고만 적고 있어 스크립트 동작과 맞지 않습니다. 그래서 네 표의 임베딩을 먼저 비우고 다시 만드는 절차를 그때의 AnchorMind 버전에서 확인해 정합니다.
- 다시 만들 때 모든 기억 원문이 Google로 가므로 사용자 승인을 받습니다. 시간과 비용은 기억 수에 비례합니다.

**3-4. 백업.** 기억이 쌓이기 시작하면 전용 DB를 주기적으로 `pg_dump`로 백업합니다. `anchormind.cmd`에 백업 동작을 더할지 정합니다.

**3-5. AnchorMind 안의 LLM 기능.** 자동 회고, 모순 판정의 LLM 단계 등은 gemini CLI가 없어 지금은 돌지 않습니다. 그대로 둘지, `codex-cli`·`agy-cli`나 Gemini API로 돌릴지 정합니다. Gemini API로 돌리면 기억 원문이 생성 모델로도 가고, 비용이 임베딩보다 큽니다.

**3-6. 모순 판정 모델 메모리.** 약 550MB를 서버가 켜져 있는 내내 씁니다. 끄는 설정이 없어 AnchorMind 코드를 고쳐야 하므로 그대로 두고, 애드온이 쓰는 동안에만 서버를 켜서 부담을 줄입니다.

**3-7. 빌드 도구 정리.** C 드라이브의 C++ 빌드 도구(약 5GB)는 pgvector를 다시 빌드할 때만 필요합니다. 팀원용 pgvector 파일은 묶지 않으므로(4단계), 이 PC에서 pgvector를 다시 빌드할 일이 없으면 지울 수 있습니다. 지울지는 사용자가 정합니다.

### 4단계: 팀원 연결 안내

- 팀원 설치 묶음(pgvector 파일, DB 만들기, `.env` 만들기)은 만들지 않습니다(2026-10-24 사용자 결정). AnchorMind는 연결해서 쓰는 외부 서비스이고, 설치와 관리는 각자 AnchorMind 공식 안내를 따릅니다.
- 안내는 `사용-안내.md`의 "AnchorMind 기억(선택 기능)"에 둡니다: AnchorMind 6.7.1을 공식 안내대로 설치 → Agora 설정에서 폴더를 고르고 변경 사항 적용 → 켜기·끄기 명령은 선택(둘 다 넣어야 Agora가 켜고 끄고, 비워 두면 연결만 하므로 AnchorMind를 직접 켜 둠).
- 각자 Gemini 키를 쓰고, 지출 한도는 AI Studio Spend 화면과 Google Cloud 예산 두 곳을 모두 확인합니다(7.4).
- 만들지 않는 것: Agora 전용 접속 키(마스터 키로 쓴 기억이 새 키에서 보이지 않음, 설계안 4.7), 모델 도구 방식(설계안 3절 방식 B).

## 6. 시험 계획

- **바뀌면 안 되는 것:** 애드온을 끈 상태에서 기존 시험이 모두 그대로 통과합니다. `reply-now-prompt-matrix`와 `question-golden`이 그대로면 프롬프트가 한 글자도 바뀌지 않았다는 뜻입니다.
- **가짜 AnchorMind 서버(로컬 HTTP):** 블록 형식, 사용자 메시지당 호출 1회, 꺼짐·시간 초과·인증·세션·AnchorMind 한도(429)·기타 오류에서 기억 없이 진행, 모든 저장에 공간 이름 포함, 관련 없는 기억 거르기, Agora가 켠 것만 끄기. 가짜 서버는 포트 0에만 열고, 실제 서버(57332)·실제 `.env`·Google은 부르지 않습니다.
- **실제 연결 1 (0단계, AnchorMind 혼자):** 공간 `agora-addon-smoke`에 저장 → 최대 5분 뒤 3,072차원(halfvec) 임베딩 확인 → 같은 공간 검색에서 찾음 → 다른 공간에서는 안 보임 → 관련 없는 질문의 점수와 근거 상태(`_meta.evidence.status`) 기록 → `forget`과 id 삭제로 0건 확인.
- **실제 연결 2 (1단계 끝, Agora와 함께):** Agora에서 기억 저장 → 새 방에서 관련 질문 → 기억 블록이 프롬프트에 들어갔는지 확인 → 관련 없는 질문에는 붙지 않는지 확인 → 지우기.

## 7. 근거가 된 시험과 확인 결과

### 7.1 임베딩 비교 (2026-10-23)

부록의 일반 문장 16개로 시험했습니다. 기억 6개, 관련 질문 8개, 관련 없는 질문 2개이고, 벡터 길이를 맞춘 뒤 코사인 유사도로 비교했습니다. "간격"은 관련 질문의 최저 점수에서 관련 없는 질문의 최고 점수를 뺀 값입니다. 양수여야 문턱값 하나로 관련 없는 기억을 거를 수 있습니다.

| 설정 | 1순위 적중 | 관련 최저 | 무관 최고 | 간격 |
|---|---|---|---|---|
| 로컬 e5-small, 384차원 | 8/8 | 0.813 | 0.851 | −0.038 |
| **Gemini 001, 1,536차원** | 8/8 | 0.693 | 0.557 | **+0.135** |
| **Gemini 001, 3,072차원(실제 연결 1, AnchorMind recall)** | 8/8 | 0.719 | 0.589 | **+0.130** |
| Gemini 2, 1,536차원, 접두어 없음 | 8/8 | 0.518 | 0.567 | −0.049 |
| Gemini 2, 1,536차원, 질문·기억 모두 접두어 | 8/8 | 0.729 | 0.590 | +0.138 |
| Gemini 2, 1,536차원, 질문에만 `query: ` | 8/8 | 0.668 | 0.513 | +0.155 |
| Gemini 2, 768차원, 접두어 없음 | 7/8 | 0.530 | 0.569 | −0.038 |

- 로컬 모델은 순위는 맞히지만 모든 점수가 0.78~0.87에 몰려서, 점수로 관련 여부를 가르지 못했습니다. 점수 범위가 모델마다 달라 문턱값도 모델마다 따로 정해야 합니다.
- `gemini-embedding-2`는 접두어 없이 쓰면 로컬 모델과 같은 문제가 생기고, 질문 앞에만 접두어를 붙여도 001 수준이 됩니다. 접두어 문구(`task: search result | query: `, `task: question answering | query: `, `query: `)에 따른 간격 차이는 0.002 이내였습니다.
- 표본이 작아서 001과 2의 우열은 가리지 못합니다. 문턱값은 실제 기억으로 다시 정합니다(2단계).
- 001은 AnchorMind의 임베딩 함수(`generateEmbedding`, OpenAI 호환 경로)와 Gemini 기본 경로에서 같은 점수가 나왔습니다. 2는 기본 경로로만 비교했고, OpenAI 호환 경로에서는 1,536차원이 돌아오는 것까지 확인했습니다.
- 속도는 001 호출 1건에 0.4~0.6초, 16문장을 차례로 보내 6~7초였습니다(로컬 1.2초). 시험 중 2에서 일시 오류(503)가 한 번 났고, 다시 보내자 정상이었습니다.
- 3,072차원 행은 0단계 실제 연결 1에서 AnchorMind `recall` 응답의 `similarity`로 잰 값입니다(애드온과 같은 인자, 2026-10-24). 위 행들은 임베딩 API를 직접 불러 잰 값입니다. 애드온 첫 문턱값은 0.679입니다. 관련 최저 0.719와 "관련 없는 쪽 최고"(무관 질문 점수와 관련 질문에 함께 온 다른 기억 점수 중 높은 쪽) 0.638의 간격 0.082가 0.05 이상이어서 규칙대로 둘의 가운데로 정했습니다(무관 질문의 최고는 0.589). 문턱값 아래로 떨어지는 관련 질문은 없습니다. 질문별(부록 순서): Q1 0.747 · Q2 0.736 · Q3 0.827 · Q4 0.745 · Q5 0.719 · Q6 0.763 · Q7 0.817 · Q8 0.724 / 무관 Q9 0.589, Q10 0.506 / 근거 상태 Q4·Q5 supported, 그 밖은 무관 질문까지 모두 partial(근거 상태로는 거르지 못함) / 관련 질문에 함께 온 다른 기억의 최고 0.638(Q8).

### 7.3 AnchorMind 구현 사실 (코드 확인)

메모리, 기동 시간, 모순 판정 모델 같은 제약은 설계안 5절에 있습니다. 여기에는 구현할 때 필요한 사실만 적습니다.

- **임베딩 호출:** 문장을 접두어 없이 그대로 보내고, 받은 벡터의 길이를 맞춰 저장합니다. 검색은 코사인 거리입니다(`lib/tools/embedding.js`).
- **차원:** AnchorMind 기본값인 3,072차원을 씁니다. 2,000차원을 넘으면 임베딩 칸이 `halfvec`으로 바뀌는데, 설치된 pgvector 0.8.7에는 `vector`→`halfvec` 암묵 변환(`CREATE CAST ... AS IMPLICIT`)이 있어 AnchorMind의 검색 쿼리(`<=> $1::vector`)가 그대로 될 것으로 봅니다. 실제 연결 1에서 저장·백필·형태소 등록·검색을 끝까지 확인했습니다(2026-10-24). `post-migrate-flexible-embedding-dims.js`가 내는 호환 경고는 이 확인 전 문구입니다. 저장 크기는 `vector(1536)`과 같습니다(2바이트×3,072 = 4바이트×1,536).
- **API 키:** `GEMINI_API_KEY`는 임베딩에만 쓰입니다. 그 밖에는 gemini CLI에 넘기는 환경 변수 목록에만 있고, 이 PC에는 gemini CLI가 없습니다.
- **의미 검색 하한:** 기본 0.4이고, 쓰면서 자동으로 조정됩니다(`config/memory.js`). Gemini 001에서 관련 없는 질문의 최고 점수가 0.557이었으므로, AnchorMind만으로는 관련 없는 기억도 돌아올 수 있습니다. 그래서 애드온에서 한 번 더 거릅니다(1-5).
- **재임베딩 스크립트:** `backfill-embeddings.js`는 임베딩이 비어 있는 기억만 채웁니다. 형태소 사전은 임베딩이 빈 낱말을 다음에 쓸 때 다시 계산합니다(`MorphemeIndex.js`).
- **LLM 단계:** 모순 판정에서 애매한 쌍을 넘기는 LLM 단계와 자동 회고는 기본값인 gemini CLI가 없어 돌지 않습니다. 리랭커는 꺼져 있어 모델을 올리지 않습니다.
- **연결 규칙:** `POST /mcp`에 Bearer 접속 키를 보내고, `initialize` 뒤에는 `MCP-Session-Id`를 씁니다. 서버 버전은 `initialize` 응답의 `serverInfo.version`에 있습니다(`lib/jsonrpc.js`). `remember`는 `content`·`topic`·`type`이 필수이고, `workspace` 없이 저장하면 모든 공간에 보이는 전역 기억이 됩니다. `forget`은 id로 지우고, 결정·에러·선호처럼 오래 남는 기억은 `force:true`가 있어야 지워집니다(없으면 `deleted:0, protected:1`로 성공처럼 옵니다).

### 7.4 Gemini 지출 한도

지출 한도는 프로젝트마다 걸리고, AI Studio의 Spend 화면 한도와 Google Cloud 예산이 따로 있습니다. 2026-10-23에는 Google Cloud 쪽 한도를 고친 뒤에도 `429 Your project has exceeded its monthly spending cap`이 계속 났습니다. AI Studio Spend 화면을 확인하도록 안내한 뒤 사용자가 한도를 풀자 바로 됐습니다. 팀원에게도 두 곳을 모두 보라고 안내합니다.

## 8. 일하는 규칙

- 시험으로 Google에 보내는 문장은 부록 같은 일반 문장만 씁니다. 프로젝트 내용이 담긴 문장을 보내는 시험은 자동 승인 검토에서 막힌 적이 있습니다. 실제 기억을 한꺼번에 다시 임베딩하는 작업은 사용자 승인을 받은 뒤에 합니다.
- Gemini 키와 접속 키는 화면, 기록, 문서에 내지 않습니다.
- 시험 스크립트는 결과를 믿기 전에 입력 문장이 제대로 찍히는지 봅니다. 2026-10-23에 Windows PowerShell이 UTF-8 파일을 다른 인코딩으로 읽어 한글이 깨진 채 Google로 보내졌고, 순위가 2~3/8로 잘못 나왔습니다. PowerShell에서 파일을 읽을 때는 `-Encoding UTF8`을 붙입니다.
- 시험용 기억은 공간 `agora-addon-smoke`에 두고, 끝나면 지워서 0건을 확인합니다.
- 커밋은 1단계의 묶음 단위로 합니다. push·병합·배포는 2절 "배포"대로 묻지 않고 하고 결과를 보고합니다.
- 자동 시험은 가짜 AnchorMind 서버(포트 0)로만 합니다. 실제 서버는 6절의 실제 연결 1·2와 화면 확인 한 번에서만 부릅니다(Gemini 사용료는 사용자 부담).
