> 상태: **구현 기록 (2026-10-11, 브랜치 `feat/question-ui`)**
> 근거: 실제 CLI 시험 `D:\Projects\Agora-review-2026-10\00-시험\00-실행중-질문-시험.md`(원본 로그 `claude-mcp/`, `codex-mcp/`).

## 1. 결정

사용자가 Claude Code·Codex와 같은 질문 UI(하나 고르기·여러 개 고르기·직접 입력)를 원했고, 핵심은 **작업 도중 던진 질문의 답이 같은 실행 프로세스로 돌아가 일이 이어지는 것**이다. 다음으로 정했다(다시 따지지 않는다).

- Claude와 Codex 모두 **실행마다 붙는 MCP stdio 도구 `ask_user` 하나**로 통일한다. 네이티브 `AskUserQuestion` 호스트 방식과 `defer → --resume` 방식은 쓰지 않는다(Codex에 못 쓰거나 세션 재개 코드 부담이 큼).
- 앱(Electron main)에 **루프백 중계소**를 하나 둔다. MCP 서버는 모델의 호출을 중계소에 HTTP로 걸어 두고, 사용자가 카드로 답하면 중계소가 그 호출에 답을 돌려준다.
- 도구 스키마는 `questions[]`(1~4개) + `multiSelect`로 넓힌다. 질문마다 보기 2~5개(없으면 직접 입력).
- **붙일 수 있는 실행에만 붙인다.** 방 권한이 파일 작업(`workspace-read`·`workspace-write`)이고 토론·도우미 턴이 아닌 **일반 대화 턴의 Claude·Codex**(§5)에만 붙는다. 대화 전용(`chat`) 권한의 턴에는 붙이지 않는다 — 대화 답은 짧아 끝에서 묻는(ASK_USER 선택지) 것으로 충분하고, 붙이면 시작이 느려지고 토큰만 는다. 파일 작업 권한의 턴에는 질문이 필요한지 미리 알 수 없어 **매번** 붙고(인사 같은 가벼운 턴도), 끄는 설정은 없다. 남는 비용은 그 턴마다 Codex 시작이 약 5초 느려지고 입력 토큰이 약 3배가 되는 것이다(§4-4). 붙지 않는 실행(대화 전용 포함)의 프롬프트·실행 인자·환경은 이전과 글자 하나까지 같고, 중계소(루프백 서버)도 그 턴 때문에 시작하지 않는다(시험 `test/question-golden.test.js`, `question-room.test.js`, `question-ipc.test.js`).
- 새 npm 의존성은 없다. MCP 서버는 node 내장 모듈(`node:http`, `node:readline`)만 쓰는 손으로 쓴 JSON-RPC이고, 패키지 앱에서는 `app.asar.unpacked`의 사본을 가리킨다(`package.json`의 `asarUnpack`).

## 2. 화면(질문 카드)

입력창 위, "답변 대기" 줄 아래에 카드가 뜬다(`src/question-card.js`, `chat.js`·`chat.html`·`chat.css`에 연결).

- 카드마다: 누가 묻는지(아바타·이름), 질문마다 질문 글 + 라디오(하나 고르기) 또는 체크박스(여러 개 고르기) + 한 줄 "직접 입력" 칸, 아래에 **[건너뛰기]**와 **[보내기]**. 보기가 없는 질문은 직접 입력 칸이 유일한 입력이다. 모든 질문에 답이 있어야 보내기가 열린다. 입력 칸에서 Enter는 답이 다 찼을 때만 보낸다(한글 조합 중 제외).
- **기타(other)**: 보기 있는 질문의 직접 입력 칸은 "기타"다. 하나 고르기에서는 기타를 쓰면 고른 보기가 풀리고(보기를 고르면 기타가 지워지고) 기타가 답이 된다. 여러 개 고르기에서는 고른 보기에 더해진다. 이를 위해 답 형식에 선택 항목 `other`를 더했다(§3).
- 입력창은 잠기지 않고, **[중지]**·**[잠깐]**은 질문 카드가 떠 있는 동안에도 보인다(`roomIsBusy()`가 카드를 센다). 중지는 질문을 닫는다. 카드가 기다리는 에이전트에게 입력창으로 메시지를 보내도 그것은 카드의 답이 아니라 기다리는 실행 뒤에 줄을 서는 새 차례다. 그래서 질문마다 한 번 "@claude가 질문 카드에 답을 기다리는 중입니다. 이 메시지는 카드에 답하거나 건너뛴 뒤 전달됩니다." 줄을 남긴다.
- 보내기가 잠겨 있으면 이유를 버튼 옆에 적는다(여러 질문이면 "아직 답하지 않은 질문: 2, 3번", 하나면 "답을 고르거나 직접 적으면 보낼 수 있어요"). 같은 글이 버튼의 `title`과 `aria-describedby`에도 걸린다. 보내기·건너뛰기로 카드가 사라지면 초점을 입력창으로 옮긴다(초점이 떨어졌거나 카드 안에 있었을 때만).
- **답을 기다리는 동안의 표시**: 카드가 그 에이전트의 질문을 기다리는 동안 입력 중 표시는 움직이는 점 없이 "Claude 답변 대기 중"이 되고, 진행 중 말풍선은 "· 답변 대기 중"과 "질문에 답하면 이어서 합니다"로 바뀐다. 처리되면 원래 표시("입력 중", "응답 중", 기다리는 사이 온 마지막 상태 글)로 돌아온다.
- **다른 방에서 기다릴 때**: 방 목록(`sessions-changed`·상태 조회)의 항목에 `waitingQuestion: true`가 실린다. 방이 이미 들고 있는 질문 기록으로 계산하고(새 조회·주기 확인 없음), 사이드바에서 그 방에 호박색 점과 "질문 대기" 글, 툴팁이 붙는다. 30분 타이머가 도는 동안 사용자를 기다린다는 신호다.
- 카드는 지금 방(sessionId)의 `pending` 질문만 그린다. 다른 방 알림은 무시하고, 방을 고르거나 창이 다시 붙을 때의 상태 스냅숏(`pendingQuestions`/`userQuestions`)이 되살린다. 처리된 질문(보냄·건너뜀·중지·중단·끝남)은 **어떤 경로로든 카드에서 사라지고**, 늦게 온 옛 '대기' 알림이 되살리지 못한다. 방 전환 직후 스냅숏이 오기 전에도 이전 방 카드는 곧바로 사라진다.
- 더블클릭 안전: 보내는 중에는 두 버튼이 모두 막히고(`보내는 중…`), 응답 전 연타는 한 번만 나간다. 실패하면 이유를 카드에 보이고 쓰던 답은 그대로 둔다. 쓰던 답은 질문 단위로 보관해 다른 알림이 와도, 방을 옮겼다 돌아와도 유지된다.
- 이미 그린 카드는 다시 만들거나 옮기지 않는다(입력 중인 글·초점이 유지되고 카드가 쌓여도 화면이 출렁이지 않는다). 카드 영역은 높이를 제한해 스크롤하므로 여러 장이어도 입력창을 밀어내지 않는다. 색은 기존 토큰(`--accent` 등)만 써서 테마를 따른다.
- 처리된 질문의 한 줄 기록은 **방(main)이 시스템 줄로 대화에 남긴다**(저장되어 다시 열어도 보인다). 예: `@claude의 질문 2개 → 답: 1) 사과, 포도, 기타 "딸기" · 2) "고마워요"`. 건너뜀·시간 초과·앱 꺼짐·중지(삭제·잠깐 포함, "@claude의 질문 2개: 중지로 닫혔습니다.")·연결 끊김("연결이 끊겨 닫혔습니다. 작업은 질문 없이 이어질 수 있습니다.")·실행 종료로 닫힌 질문도 한 줄로 남고, 다시 켠 뒤 중단된 질문은 카드가 아니라 이 한 줄뿐이다. 여러 줄로 쓴 답도 이 줄에서는 공백을 한 칸으로 줄여 한 줄이다(전체 답은 질문 기록에 그대로 있다). 시스템 줄은 AI 프롬프트에 들어가지 않는다.
- 사용자에게 보이는 안내는 쉬운 말만 쓰고 원인 오류 글은 콘솔 로그에만 남긴다. 예: 붙이지 못했을 때 "@claude: 작업 중 질문 기능을 켜지 못했습니다. 이번에는 답변 끝에서 선택지로 묻습니다."

## 3. 답 형식과 모델이 읽는 글

`answers[i]`는 `questions[i]`에 대응한다.

| 질문 | 답 |
|---|---|
| 보기 있음 | `{ selected: [보기 문구…], other?: "기타 직접 입력" }` — 하나 고르기는 보기+기타를 합쳐 정확히 1개(보기 대신 기타면 `selected: []`), 여러 개 고르기는 합쳐 1개 이상, 중복 불가. `other`는 1~8000자 |
| 보기 없음 | `{ text: "직접 입력" }` 1~8000자 |

보기 있는 질문에 `text`를 보내는 것은 여전히 거절한다. 모델에게는 도구 결과로 `Q: …` / `A: …` 블록이 가고, 기타는 `(기타 직접 입력) "…"`처럼 따옴표로 감싸 보기 문구와 섞이지 않게 한다. 결과 끝에는 "이 답은 도구·파일 사용을 허락한 것이 아니다"라는 문장이 붙는다.

## 4. 실제 CLI 시험에서 나온 함정(반영함)

1. **Claude는 `--allowedTools mcp__<서버키>__ask_user`가 필수.** 빼면 `-p`에서 도구가 거부되고 모델이 "권한을 달라"고만 답한다. 서버 키(`agora_user_question`)를 상수로 고정하고 허용 도구 이름도 그 상수에서 만든다.
2. **Codex는 `tool_timeout_sec`이 필수.** 기본 60초라 사용자가 1분 넘게 고민하면 도구 호출이 실패하고 질문이 취소된다. 그래서 Codex 인자에 `-c mcp_servers.agora_user_question.tool_timeout_sec=2100`(35분)을 붙인다(Claude에는 같은 목적으로 환경 변수 `MCP_TOOL_TIMEOUT=2100000`을 더했다 — Claude 쪽 기본 한도는 오프라인에서 확인하지 못해 방어적으로 둔 값이다). **중계소의 대기 상한(30분)보다 5분 길게** 둔 것은 일부러다. 같거나 짧으면 CLI가 먼저 포기해 중계소가 "30분 안에 답하지 않았습니다. 같은 질문을 되풀이하지 말고…"(`timeout`) 결과를 돌려주지 못하고, 연결 끊김 경로로 빠져 모델이 같은 질문을 되풀이할 수 있다. `question-argv`·`question-ipc` 시험이 CLI 제한이 중계소 대기보다 긴지 확인한다.
3. **Codex는 프롬프트에 서버·도구 이름이 있어야 쓴다.** 안내 없이는 8번 중 0번 썼고(자체 도구를 시도하거나 "도구가 없다"고 답함), 안내를 넣으면 4번 중 4번 썼다. 그래서 질문 도구가 붙은 실행의 프롬프트에만 사용 안내(`USER_QUESTION_INSTRUCTION`)를 더한다.
4. 노력(effort)은 항상 명시한다(사용자 Codex 설정이 xhigh면 가장 비싼 값이 상속된다). 질문 도구를 붙인 Codex는 시작 지연이 약 5초, 입력 토큰이 약 3배다. 시험 메모는 필요한 실행에만 붙이라 했다. "필요"를 미리 알 수는 없으므로 **파일 작업 권한의 일반 대화 턴에만** 붙이고(§1), 대화 전용 턴에는 붙이지 않아 그 비용을 없앴다. 파일 작업 권한의 턴에서는 가벼운 요청에도 이 비용이 그대로 든다 — 끄는 설정이나 요청 내용을 보고 정하는 문턱은 없고 뒷날 과제로 남긴다.
5. 대기 중에는 Agora의 실행 시간 제한과 무음 경고를 멈추고, 답 뒤 남은 시간만 다시 건다. 기다린 시간은 실행 지표에 `userWaitingMs`·`modelDurationMs`로 따로 남는다.

## 5. 어디에 붙고 어디에 붙지 않는가(한계)

- **붙는 곳**: 방 권한이 파일 작업(읽기·쓰기)인 일반 대화·작업 턴, Claude와 Codex, CLI를 직접 실행하는 설치(`claude.exe`, `codex.exe`). 이 조건이면 매 턴 붙는다(§1).
- **붙지 않는 곳**
  - **대화 전용(`chat`) 권한의 방**: 답이 짧고 끝에서 묻는 선택지(칩)로 충분하다. 도구도, 설치 방식 안내도, 중계소 시작도 없다.
  - **셸 래퍼(`.cmd`) 설치**: 실행 인자를 그대로 믿고 이어 붙일 수 없어 붙이지 않는다(아틀리에도 미지원).
  - **토론·결론 종합·쉽게 설명 턴**: 사용자가 끼어드는 흐름이 아니라 붙이지 않는다.
  - **AGY(Antigravity)**: 실행 단위로 MCP 설정을 줄 수단이 없다. 응답 끝에서 묻는 기존 ASK_USER 방식(칩, 여러 개 고르기, 직접 입력)이 그대로 쓰인다.
- 붙이지 못하면 방이 이유를 알리고(설치 방식 때문에 못 붙이면 에이전트마다 한 번 "@codex는 설치 방식 때문에 작업 중 질문 기능을 쓸 수 없습니다. 결정이 필요하면 답변 끝에서 선택지로 묻습니다." 줄을 남긴다. 이 줄은 도구가 붙었을 턴에만 나온다 — 대화 전용 방·토론·도우미 턴·AGY는 원래 붙는 대상이 아니라 알리지 않는다), 프롬프트도 도구 없는 예전 모양으로 실행한다. 도구가 붙은 실행에서도 끝 ASK_USER 줄은 대체 수단으로 남는다.
- 같은 방의 다른 응답은 실행 중인 응답이 답을 기다리는 동안 차례를 기다린다(안내 문구에 질문에 답하면 이어진다고 알린다).
- 사용자가 건너뛰었거나 시간 초과된 실행에는 중계소가 더 묻는 호출을 거절하고(`refused`), 세 번째 거절에 방이 그 실행을 멈추고 알린다. 한 실행의 질문은 20번까지다.
- 사용자가 답하는 데 걸리는 시간 상한은 30분(그 뒤 질문을 닫고 모델이 답 없이 이어 가게 한다).

## 6. 끝내기: 질문이 방을 막지 않는다

중지·잠깐·세션 삭제·앱 종료·실행 종료·재시작은 대기 중인 질문을 풀고 중계소 등록을 푼다. **창 닫기는 질문을 풀지 않는다** — 앱은 트레이에 남아 질문은 그대로 대기 중이고 30분 타이머도 계속 돈다. 창이 다시 붙으면 카드가 되살아나 답할 수 있고, 아무도 답하지 않으면 30분 뒤 `timeout`으로 닫힌다. 일반 대화로 돌아가는 길은 어떤 경우에도 막히지 않는다.

| 상황 | 질문 상태(`reason`) | 비고 |
|---|---|---|
| 답을 보냄 | `submitting` → `answered` | MCP가 도구 결과를 썼다고 확인하면 `answered` |
| 건너뛰기 | `cancelled` (`user-skip`) | 모델은 "답하지 않기로 했다" 결과를 받는다 |
| 중지·잠깐·삭제 | `cancelled` (`stopped`) | 프로세스도 끊는다. 대화에 "@claude의 질문 N개: 중지로 닫혔습니다." 한 줄 |
| 30분 무응답 | `cancelled` (`timeout`) | 모델은 "더 묻지 말라"는 결과를 받는다. CLI 도구 제한이 35분이라 이 결과가 먼저 닿는다(§4-2) |
| CLI가 호출을 먼저 끊음·중계소 서버 오류 | `cancelled` (`connection-lost`·`server-error`) | 실행은 계속될 수 있다. 대화에 "연결이 끊겨 닫혔습니다. 작업은 질문 없이 이어질 수 있습니다." |
| 실행이 질문 중 끝남 | `cancelled` (`run-ended`) | 답을 보낸 뒤 전달 확인 전에 끝나면 결과가 성공일 때 `answered`, 아니면 `interrupted` |
| 앱 종료 | `interrupted` (`app-quit`) | |
| 다시 켬 | `interrupted` (`app-restart`) | 기록에만 남고 답할 수 없다. 대화에 한 줄이 한 번만 남는다 |

창이 닫혀 있던 사이에 온 질문은 창이 다시 붙을 때 상태 스냅숏으로 되살아나 답할 수 있다.

## 7. 무엇이 저장되는가

- 대화 기록(`.agora`의 대화별 기록)에 질문 이벤트 `user_question_requested`, `user_answer_submitted`, `user_answer_delivered`, `user_question_cancelled`, `user_question_interrupted`가 상태마다 한 줄씩 쌓인다. **질문 글과 사용자가 쓴 답(직접 입력 포함)이 그대로 저장되므로** 민감한 내용을 직접 입력하면 그 대화의 기록 파일에 남는다. 다시 켤 때는 질문별 마지막 줄이 그 질문의 상태다. 질문 기록은 방당 200개까지 기억한다.
- 대화 화면에 보이는 시스템 줄(§2)은 일반 대화 메시지로 저장된다.
- 실행별 중계소 토큰(무작위 32바이트)은 디스크에 쓰지 않고 로그에도 남지 않는다. 다만 **CLI 명령줄에는 들어간다** — Claude는 `--mcp-config` JSON의 서버 환경에, Codex는 `-c mcp_servers…env={…}` 인자에 담겨 MCP 서버 프로세스의 환경으로 전달된다. 그 실행 중에는 같은 컴퓨터에서 같은 사용자의 프로세스 목록(그리고 쓰기 권한 모드에서 모델의 셸 도구)이 볼 수 있다. 한계: 이 토큰은 **그 실행 하나에만, 그것도 질문(ask)과 전달 확인(delivered)에만** 쓸 수 있고 실행이 끝나면 죽는다. 사용자 답을 읽거나 다른 실행·방에 쓰는 데는 쓸 수 없다. 환경 변수나 파일·상속 핸들 같은 다른 전달 수단은 무게 대비 위험이 작아 쓰지 않는다(`claude-live-credentials`도 같은 인자 방식이다). 중계소는 `127.0.0.1`의 임시 포트에만 열리고, MCP 서버의 요청은 프록시 환경 변수를 무시하고 직접 연결한다. 토큰이 없거나 끝난 실행의 요청은 거절한다.
- 질문 기록을 디스크에 쓰지 못해도 질문·답·실행은 멈추지 않고 알림이 한 번 나온다.

## 8. 아틀리에와의 차이

참고 구현(아틀리에 `d99764c5`)에서 가져온 것은 중계소·MCP 서버·붙이기 구조이고, 다음은 다르다.

- 질문이 **한 개가 아니라 1~4개 묶음**이고 `multiSelect`가 있다. 답은 질문 순서대로 돌려준다.
- 카드는 대화 목록 안이 아니라 **입력창 위**에 뜨고, 처리되면 사라지며, 처리 기록은 시스템 줄로 남긴다. 아틀리에는 카드를 대화 목록 안에서 `createdAt`으로 끼워 넣어 상태 알림이 올 때마다 카드를 통째로 다시 만든다(그래서 쓰던 글이 사라질 수 있다). Agora 카드는 쓰던 답을 질문 단위로 보관하고 다시 만들지 않는다.
- 전문 모드·역할 상담·워크스페이스 lease가 없고, 승인 대기·방 이벤트 리스너 보호막(`on()` 래퍼)·중지/잠깐 버튼을 그대로 쓴다.

## 10. 검증 뒤 고친 것

실제 CLI·Electron 스모크·독립 검토 세 갈래를 거친 뒤 고친 것: 질문 카드 높이(보내기 줄 고정), `.cmd` 안내, **파일 작업 권한 턴에만 붙이기**(§1), CLI 도구 제한 35분(§4-2), 연결 끊김·중지·여러 줄 답의 대화 줄(§2·§6), 답을 기다리는 동안의 표시·초점·보내기 안내·사이드바 표시(§2), 카드 대기 중 메시지 안내, 프록시 우회·서버 오류 처리기, 쉬운 말 안내.

남은 한계: 파일 작업 권한의 턴은 가벼운 요청에도 도구가 붙고 끌 수 없다(Codex 약 5초·입력 토큰 약 3배), 토큰이 CLI 명령줄에 들어간다(§7), 도구 서버가 시작에 실패해도 사용자에게는 알리지 않고 모델이 도구 없이 답할 뿐이다.
