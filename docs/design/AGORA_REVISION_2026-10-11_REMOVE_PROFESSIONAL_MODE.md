# Agora — 개정 기록 2026-10-11: 전문 모드·역할 상담 제거

> 상태: **사용자 결정 반영 기록 (2026-10-11)**
> 근거 규칙: [Stage D Charter §8 문서 개정 규칙](AGORA_STAGE_D_ASSURANCE_CHARTER.md) — 개정 사유와 날짜 누적 기록, 불변식 삭제 시 막던 실패 모드와 대체 통제 명시.

## 1. 결정

2026-10-11, 사용자가 다음을 결정했다: **"전문모드 그냥 제거하고, 오케스트레이터로 전환"**.

- 전문 모드(일반/전문 토글, PLAN / 실행 / 전체 실행, Planner · Plan Reviewer · Builder · Reviewer · Recorder 파이프라인, Stage D assurance, 체크포인트, TASK.md 흐름)를 제거한다.
- 역할 상담(`@기획자` `@검토자` `@구현자` `@기록자` `@팀`, `@팀 실행`)을 제거한다.
- 워크스페이스 변경 lease(Stage D-0)도 제거한다. lease는 전문 모드 제거와 같은 단계가 아니라 후속 단계(stage 4)에서 지웠다. 두 대화가 같은 폴더에서 동시에 일할 수 있다(§4a).
- 일반 대화 안의 오케스트레이터 모드는 **후속 작업**으로 추가한다. 이 개정 기록은 그 설계를 확정하지 않는다.

## 3. 유지되는 것

일반 대화와 `@모두`·에이전트 간 `@mention` 호출, 자유/구조화 토론, 전달(handoff)·쉽게 설명, 첨부, 승인 후 재실행(턴 단위 승인 카드), 답변 대기(ASK_USER/OPTION), 워크스페이스 권한(대화만/읽기/쓰기), 프로젝트 기록(memory·decisions·tasks 저장소와 팝오버, memoryContext/rulesContext/workflowContext 주입, 끝난 토론의 자동 기록), 사용량·계정·설정, 1회 CLI 실행 어댑터.

자동 기록(보존): 끝난 토론은 **기록 담당을 정한 프로젝트에서만** 기록한다. 담당은 프로젝트 설정 한 줄 "토론 자동 기록"(프로젝트 필드 `recordAgent`: 에이전트 id, 빈 문자열 = 기록 안 함)이 정하고, 이 필드가 없으면 v1.1.1과 같이 옛 `defaultRoles.recorder`(없으면 `review`)의 에이전트·모델·노력도를 따른다. 둘 다 없으면 기록하지 않으며(모델 호출도, 기록 저장도 없음) 담당이 꺼져 있거나 쓸 수 없으면 조용히 건너뛴다. 설정 화면은 실제 적용값을 보여 주므로 옛 역할로 기록을 맡기던 프로젝트는 그 에이전트가 선택된 채로 보인다. 옛 `defaultRoles` 키는 파일에 그대로 남는다.

## 4. Charter §8: 불변식 삭제 처리

Stage D 불변식(INV-1~5, R-1~8 등)은 "전문 모드의 실행·검증·완료 판정"을 통제하려는 것이었다. 그 대상 기능이 사라지므로 불변식은 **적용 대상이 없어져 폐기**된다(완화가 아니라 대상 소멸).

- 막던 실패 모드: 계약 없는 완료 선언, 검증 불가 항목의 거짓 통과(`UNSUPPORTED → PASS` 세탁), 동시 변경 충돌, 판정 사후 수정.
- 대체 통제: 쓰기는 워크스페이스 권한(대화만/읽기/쓰기)과 `minPermissionMode`가 계속 제한하고, 승인이 필요한 턴은 턴 단위 승인 카드를 거치며, 사람만 정할 수 있는 질문은 답변 대기로 올린다. 오케스트레이터에 필요한 추가 통제는 그 설계 단계에서 별도 개정으로 정한다.
- lease 제거 시점의 동시 변경 보호는 아래 §4a에 기록한다.

## 4a. 워크스페이스 변경 lease 제거 (2026-10-11, stage 4)

사용자 결정: 같은 작업 폴더를 두 대화가 동시에 써도 된다. `src/agora/workspace-mutation-lease.js`, ChatRoom의 획득·해제·승인 대기 중 반납과 재획득, 독립 발언 묶음의 그룹 lease, `WORKSPACE_BUSY` 경로와 그 안내 문구, chat-ipc의 lease 생성·주입·세션 삭제 시 정리, 그 시험을 모두 지웠다. 쓰기 방의 턴은 다른 대화의 턴을 기다리거나 거절당하지 않고 곧바로 실행된다. 토론도 다른 대화의 턴 때문에 끊기지 않는다. 같은 방 안의 턴 순서(큐·펌프)는 그대로다.

막던 실패 모드와 지금 남은 위험(대체 통제 없음, 사용자가 감수):

- 같은 파일을 두 대화가 동시에 고치면 나중에 쓴 쪽이 이긴다(last-write-wins). 조용히 덮어써질 수 있다.
- `git`의 `index.lock`, 패키지 설치, 빌드처럼 폴더 전체에 영향을 주는 명령이 서로 부딪힐 수 있다.
- Windows에서는 다른 쪽이 연 파일이 잠겨 쓰기·삭제가 실패할 수 있다.

같은 방의 독립 발언(`@모두` 등을 동시에 실행)은 예전과 같이 담당자별 폴더 계약(`claude/`, `codex/` …)을 프롬프트로 주고, 실행이 끝난 뒤 담당자 폴더 밖에서 바뀐 파일을 찾아 알린다. 이 감시는 lease와 무관하게 쓰기 권한 방에서만 켜지며, 알림 문구는 "이 묶음이 실행되는 동안 담당자 폴더 밖에서 바뀐 파일(다른 대화나 직접 수정일 수 있음)"이라고 말한다(다른 대화나 사용자가 같은 시간에 바꾼 파일도 잡히므로 담당자 탓으로 단정하지 않는다). 쓰지 않는 `supportsPersistentSession` 플래그도 함께 지웠다.

## 5. 기존 문서의 처리

설계 문서는 **삭제하지 않고 기록 보존용으로 둔다.** Stage C · Stage D · D-0 · D-A0 문서와 V1/V1.5 문서의 전문 모드 부분 맨 위에 "대체됨(superseded) 2026-10-11" 안내를 붙였다. 본문은 고치지 않았다.

## 6. 사용자 데이터

이전 버전이 남긴 `~/.agora/sessions/*/checkpoints`, `professional-events.jsonl`, `<workspace>/.project-memory/`는 지우거나 다시 쓰지 않는다. 앱은 이 폴더를 해석하지 않으며, 예외로 `.project-memory/tasks/*.md`만 작업 카드 본문을 보여 주기 위해 읽기 전용으로 읽는다(아래 참고).

세션 `meta.json`의 `professionalRun`·`pendingRecovery`는 **있는 그대로 보존하고 해석하지 않는다**. 대화를 저장할 때마다 meta.json은 통째로 다시 저장되므로 파일이 다시 쓰이지만, 이 두 필드의 값은 바뀌지 않은 채 함께 기록된다("다시 쓰지 않는다"가 아니라 "지우지도 바꾸지도 않는다").

`run-logs/*.evidence.json`과 파일 기반 작업 카드(`contentSource: "file"`)의 본문(`<workspace>/.project-memory/tasks/TASK-*.md`)도 그대로 둔다. 실행 로그 정리는 `.log`만 다루므로 옛 evidence 파일은 지워지지 않고, 파일 기반 작업 카드는 본문을 읽기 전용으로만 보여 준다(`chat:tasks:read-file`, 프로젝트 폴더의 `.project-memory/tasks/*.md`·256KB 이하·폴더 밖을 가리키는 링크 거절).

프로젝트 JSON(`~/.agora/projects/*.json`)의 옛 `defaultRoles`·`autoRevisions` 키도 지우거나 다시 쓰지 않는다. 읽을 때만 걸러 내고, 프로젝트를 수정해 저장해도 파일에는 그대로 남는다(v1.1.1로 되돌려도 설정이 유지된다).
